# mushy-lint agent guidelines

mushy-lint extracts complete source constructs with tree-sitter and reports raw
classification scores. Development is mirrored from `pub/mushy-lint/` in the
monorepo to `napisani/mushy-lint`. In the monorepo, run
`make check FILTER=mushy-lint` before calling work done. In a standalone checkout,
run `bun run typecheck`, `bun run lint`, `bun run test`, and `bun run build:bin`.

## Contracts

- Configuration uses version 2 only. Resolve document-level targets, conditions,
  file sets, and glob lists once; references have no template or inheritance rules.
- Discovery and sampling share source-analysis file matching. Record sampling
  scope/seed and per-rule zero coverage; sampling never establishes compliance.
- Review artifacts contain source. Create new private directories, keep raw scores
  and all failures, and leave semantic decisions to the reasoning agent.
- A target defines a root capture, source evidence, and one reporting location.
  Query captures are lists of complete strings. `location` defaults to `root`.
- A rule's `score` is a yes/no question. A result's numeric `score` is raw p(yes).
  This is distinct from TypeSafe's ordinal Score primitive. Preserve raw answers.
- `includeIf` only gates classification. Search the entire root subtree, including
  nested constructs, without changing evidence or reporting location.
- A plan snapshots evidence without provider wire types or live parser handles.
  Reuse plans to compare providers rather than reparsing for each provider.
- Every eligible rule-target pair has one terminal result. Extraction, missing
  context, size, and request failures are explicit `not_evaluated` results or
  file/run issues when affected targets cannot be established.
- All matching sections apply. Exact duplicate capture-span matches collapse;
  inference answer reuse never collapses separate source results.

## Ownership

Source analysis owns grammar/query execution and eligibility. Classification owns
provider adapters, shared-state question batching, exact-work reuse, rate limits,
retries, and response validation. Reporting formats evidence and coverage without
inference or score interpretation. Provider SDK/wire types stay in adapters.

Current providers use native System One probabilities. OpenRouter's dedicated
System One route is documented separately from chat completions. Keep transport
contract fixtures and runtime probability validation when adding providers.

Cross-file context providers, executable custom extractors, persistent caching,
and cross-state prompt packing remain outside the implemented scope. Required
unsupported context is explicit rather than silently supplied as empty evidence.

## Parsing and verification

WASM grammars are pinned in `grammars/grammars.json`; rebuild through the package
script. WASM file imports must keep their byte-loading behavior so compiled Bun
binaries can embed the runtime and grammars. TypeScript and TSX use separate
languages. Dispose trees, queries, and parsers at their ownership lifetime.

The grammar can recover incorrectly around unsupported TypeScript syntax. Report
incomplete file coverage and avoid classification of captures touching invalid
syntax; valid unrelated targets can still be evaluated. Never silently truncate
an attached construct.

Use real grammar fixtures and local HTTP contract tests. Mock only the external
classification seam, not syntax extraction or module imports. Record model IDs
and provider-supplied usage without inventing missing metadata.

Lint configuration and `tools/oxlint/` are generated by `pub/lint/sync-lint-config.ts`.
Change the shared catalog rather than generated rules. Deliberately invalid code
belongs under `tests/fixtures/`, which is excluded from lint and typecheck.
